## 3. 데이터 품질 위험 (DQ)

각 항목은 가설, 위험, 검증 방법, 제안, 완료 기준 순서입니다.

### DQ-1. A·L 겹침 구간의 이중 집계 — 우선순위 최상

- **가설**: 공통 중복 제거가 `uts+artist+track` **완전 일치**만 잡습니다. Apple 로그 시각과 Last.fm 스크로블 시각은 보통 몇 초~몇 분씩 어긋나기 때문에, 겹치는 기간(2025-01 ~ 2026-09-09)에 같은 재생이 두 번 집계될 수 있습니다.
- **위험**: 이 기간의 모든 통계(Top, 추이, 다양성, 프롬프트)가 부풀려집니다.
- **검증 방법**
  1. 월별·소스별 일평균 재생 수 표를 만듭니다. 겹치는 달의 합계가 겹치지 않는 달보다 눈에 띄게 높은지 확인합니다.
  2. 겹치는 기간에서 A와 L의 행 쌍 중 정규화한 `artist+track`이 같고 `|Δt| ≤ max(곡 길이, 300초)`인 쌍의 수를 셉니다.
  3. 현재 CSV에서 겹치는 구간에 두 소스가 **실제로 함께 있는지**부터 확인합니다. 이미 수동으로 병합했다면 쌍의 수는 0에 가까워야 합니다.
- **제안**
  - 겹치는 구간은 Apple 로그를 기준 소스로 삼고, L은 A가 없는 시간대에서만 사용합니다.
  - 또는 위 퍼지 매칭으로 L 쪽을 `status=dup_of_A`로 표시합니다.
  - 이 단계를 스크립트로 자동화해서, 새 Apple 내보내기를 받았을 때 그대로 재실행할 수 있게 합니다.
- **완료 기준**: 겹치는 구간의 퍼지 매칭 쌍이 0건이고, 월별 일평균 그래프가 소스 경계에서 튀지 않습니다.

### DQ-2. 소스 전환 시점의 가짜 "발견"

- **가설**: A가 끝나는 2026-09-09 이후 L만 남습니다. A와 L의 표기가 다르면(현지화된 아티스트명, `feat.` 표기, `(Remastered)` 같은 꼬리표) 같은 곡이 새로 발견한 곡으로 잡힙니다.
- **검증 방법**
  - 2026-08 ~ 10월의 월별 신규 트랙/아티스트 수를 확인합니다.
  - 9/9 이후 "처음 들은" 곡 중에서, 정규화(소문자, 공백·기호 제거, 괄호 꼬리표 제거)하면 기존 곡과 같아지는 곡 목록을 뽑습니다.
  - A와 L에서 아티스트명이 다르게 표기된 쌍(예: 한글 표기와 영문 표기)을 찾습니다.
- **제안**: 정규화 키를 도입하고, 쌍 목록을 바탕으로 별칭 파일을 보강합니다(ACC-1과 연결).
- **완료 기준**: 9~10월 신규 수가 이전 달 추세 범위 안에 들어옵니다.

### DQ-3. 전처리 멱등성

- **가설**: 새로고침할 때마다 전처리가 돕니다. 판정 규칙이 이웃한 행 관계("같은 초에 겹침" 등)에 의존하기 때문에, 한 번 제거하면 이웃 관계가 바뀌어 다음 실행에서 또 다른 행이 제거될 수 있습니다.
- **검증 방법**
  - CSV 복사본에 전처리를 두 번 연속 실행합니다. **두 번째 실행에서 추가로 제거된 행이 0건**이어야 합니다.
  - 전처리가 전체 데이터에 적용되는지, 새 행에만 적용되는지 코드에서 확인합니다.
- **제안**
  - 판정은 "새로 들어온 행과 그 앞뒤 경계 구간"에만 적용하고, 처리 완료 지점(watermark)을 저장합니다.
  - 멱등성 테스트를 자동 테스트로 추가합니다.
- **완료 기준**: 두 번 실행해도 추가 제거가 0건이라는 테스트가 통과합니다.

### DQ-4. 원본 덮어쓰기

- **가설**: 전처리 결과가 원본 CSV를 덮어씁니다(백업은 있음).
- **위험**: 오탐률이 약 15%인 규칙을 나중에 고쳐도, 원래 데이터에서 다시 계산하기 어렵습니다.
- **제안**
  - `raw`(수집한 그대로, 추가만 가능)와 `clean`(파생 결과)을 분리합니다.
  - 제거·보류는 행을 지우지 말고 `status` 열(`ok / removed_fake / removed_dup / hold`)로 표시합니다.
  - 화면에서 "보류 건 포함/제외"를 토글할 수 있게 합니다.
- **완료 기준**: `clean`을 지우고 `raw`에서 재생성했을 때 같은 결과가 나옵니다.

### DQ-5. 늦게 도착하는 스크로블 누락

- **가설**: `callData.py`가 "마지막 저장 시각 이후"만 받아 옵니다. Last.fm은 오프라인 재생분처럼 과거 시각의 스크로블을 나중에 받아들일 수 있기 때문에, 그런 기록은 영원히 빠질 수 있습니다. 허용되는 과거 범위는 Last.fm API 문서로 확인해 주세요.
- **검증 방법**: 수집 시작 시각을 어떻게 정하는지 코드에서 확인하고, 최근 14일을 다시 받아서 현재 CSV에 없는 행이 있는지 비교합니다.
- **제안**: 매번 최근 N일(예: 14일)을 겹쳐서 받아 오고 중복을 제거합니다.
- **완료 기준**: 겹쳐 받은 구간의 차이가 0건이거나, 차이가 나면 자동으로 보충됩니다.

### DQ-6. 누락 구간 미표시

- **가설**: 10/08~10/18 같은 공백이 주간·월간 프롬프트에서 "청취 급감"으로 해석됩니다.
- **제안**
  - "누락 의심일"을 자동으로 감지합니다. 예: 그날 재생 수가 직전 28일 중앙값의 20% 미만이고, 그 중앙값이 10 이상인 날.
  - 히트맵, 프롬프트, 데이터 상태 화면에 표시합니다. 프롬프트에는 "이 기간은 기록 누락 의심"이라는 주석을 답니다.
  - 나중에 Apple 사본으로 채울 때 그 구간의 일부 L 기록과 겹치지 않는지 DQ-1 로직으로 확인합니다.
- **완료 기준**: 10/08~10/18이 자동으로 표시되고, 정상적인 날이 잘못 표시되는 비율이 낮습니다.

### DQ-7. CSV 쓰기와 동시 읽기

- **가설**: 새로고침이 CSV를 쓰는 동안 다른 API 요청이 읽으면 일부만 읽히거나 오류가 납니다.
- **제안**: 임시 파일에 쓴 뒤 `os.replace`로 원자적으로 교체하고, 쓰기 작업에는 잠금을 겁니다.

### DQ-8. 스크로블러 교체 후 규칙 재검증

- **가설**: 허구 백필 판정 규칙은 이전 스크로블러의 패턴에 맞춰져 있습니다. FastScrobbler로 바꾸면 패턴이 달라질 수 있습니다.
- **제안**: 교체 후 1~2주 동안 일별 제거·보류 건수를 기록하고 이상치를 확인합니다.

### DQ-9. 수면 세션 포함 여부

- 지금은 주석만 달고 모든 통계에 포함합니다.
- **제안**: "수면 의심 세션 제외" 옵션을 추가합니다. 시간대와 다양성 지표가 깨끗해집니다.

## 4. 정확도 개선 (ACC)

### ACC-1. 별칭을 집계 전체에 적용 — 우선순위 최상

- **가설**: `config/artist_aliases.txt`가 태그 조회에만 쓰이고, Top·다양성·발견 집계에는 적용되지 않습니다.
- **검증 방법**: 별칭 파일을 읽는 코드 위치를 찾습니다(`grep -rn artist_aliases`). 데이터 로딩 함수에서 적용되는지 확인합니다.
- **제안**: 데이터 로딩 단계에서 별칭을 전역 적용하고, 원래 이름은 `artist_raw` 열로 보존합니다.

### ACC-2. 앨범·트랙 키에 아티스트 포함

- **가설**: 앨범을 `album`만으로 묶으면 "Greatest Hits", "Intro" 같은 흔한 이름이 서로 합쳐집니다.
- **검증 방법**: Music Top과 다양성 계산의 groupby 키를 확인합니다.
- **제안**: 앨범은 `artist+album`, 트랙은 `artist+track`을 키로 씁니다. 컴필레이션처럼 artist가 빈 행은 별도로 처리합니다.

### ACC-3. 다양성 지표의 기간 비교 가능성

- 정규화 엔트로피는 고유 항목 수(N)에 따라 값이 달라져서, 날짜 필터 길이가 다르면 비교에 착시가 생깁니다.
- **제안**: **유효 아티스트 수(exp(H), Hill number)**를 함께 표시합니다. 기간끼리 비교할 때는 같은 표본 크기로 맞춘(rarefaction) 값을 씁니다.

### ACC-4. 태그 노이즈와 표기 정규화

- **제안**
  - 블랙리스트를 둡니다(예: seen live, favorites, 국가명, 아티스트 자체 이름).
  - 표기를 정규화합니다(소문자, 하이픈과 공백 통일: hip hop / hip-hop / Hip-Hop).
  - 블랙리스트는 설정 파일로 관리합니다.

### ACC-5. 커버리지를 재생 기준으로 표시하고 조회 순서 바꾸기

- 지금은 "N / 전체 아티스트" 기준이지만, **재생 수 기준 커버리지**가 실제 의미에 가깝습니다.
- 태그 미리 불러오기를 재생 수 내림차순으로 진행합니다.

### ACC-6. 발견 워밍업 구간

- 데이터 시작(2024-06) 후 몇 달은 예전부터 듣던 곡도 신규로 잡힙니다.
- **제안**: 첫 3~6개월을 워밍업으로 지정하고 차트에서 흐리게 표시하거나 제외하는 옵션을 둡니다. Apple 라이브러리에 추가 날짜 필드가 **있다면** 그것으로 보정하는 방법도 검토해 주세요.

### ACC-7. KST 날짜 경계의 일관성

## 6-1. FEAT-7 기간 비교 상세 명세 (사용자 요청)

**목표**: 두 기간(A, B)을 골라 같은 기준으로 나란히 비교합니다. 지금은 연간/월간/주간 프롬프트에서 "직전 기간"과 비교하는 것만 가능하고, 화면에서는 비교할 수 없습니다.

**기간 선택**

- 위치: 새 탭 `Compare`. 상단 날짜 필터와 별개로 A·B 선택기 두 개를 둡니다.
- 프리셋: 직전 같은 길이 기간 / 전년 같은 기간 / 두 달 고르기 / 두 해 고르기 / 직접 입력.
- 기본값: A는 현재 상단 날짜 필터, B는 A 바로 앞의 같은 길이 기간.
- A와 B가 겹치면 경고만 띄우고 막지는 않습니다.

**공정한 비교를 위한 규칙**

- 두 기간의 길이가 다르면 모든 양적 수치를 **총량과 일평균으로 함께** 보여 줍니다.
- 일평균의 분모는 누락 의심일(DQ-6)을 뺀 일수로 하고, 뺀 날 수를 화면에 표시합니다.
- 기록이 기간 끝까지 닿지 않으면 "일부 기간"으로 표시합니다(기존 프롬프트 규칙과 같음).
- 다양성은 정규화 엔트로피 대신 다음 두 가지를 씁니다(ACC-3).
  - 유효 아티스트 수
  - 두 기간 중 재생 수가 적은 쪽에 표본 크기를 맞춘 값

**비교 항목**

| 블록 | 내용 | 표시 방식 |
|---|---|---|
| 요약 | 총 재생, 일평균, 청취 시간(분, FEAT-2), 청취한 날 수, 고유 아티스트·트랙·앨범 수, 유효 아티스트 수, 신규 발견 수 | A / B / 증감(%) 표 |
| 순위 | Top 아티스트·트랙·앨범 (기본 10개, 개수 선택 가능) | 두 열을 나란히 놓고 ▲▼ 순위 변동, NEW, B에만 있던 항목 표시 |
| 겹침 | 두 기간 모두 들은 아티스트 / A에만 / B에만, 겹침 비율 | 숫자 + 세 그룹별 상위 목록 |
| 장르·언어권 | 태그 비중, 언어·지역권 비중 | 차이 막대(diverging bar) |
| 시간 패턴 | 시간대 분포, 요일 분포 | 두 기간을 한 차트에 겹쳐 그림 (청취 시계 두 겹) |
| 발매연도 | 연대 분포 (FEAT-1 완료 후) | 겹친 막대 |

**AI 프롬프트 연동**

- 비교 화면에 "이 비교로 AI 프롬프트 만들기" 버튼을 둡니다. 지금 프롬프트는 연/월/주 단위로 고정되어 있는데, 이 버튼으로 임의의 두 기간을 비교하는 프롬프트를 만들 수 있게 됩니다.

**구현 방향**

- 백엔드: `summarize_period(df, start, end)` 공통 함수를 만들고, 연간·월간·주간 프롬프트와 compare API가 모두 이 함수를 쓰게 합니다. **같은 비교 로직이 두 군데로 갈라지지 않게 하는 것이 핵심**입니다.
- API: `GET /api/compare?a_start=&a_end=&b_start=&b_end=&limit=` → `{a: 요약, b: 요약, diff: 증감·순위 변동·겹침}`.
- 프론트엔드: `tabs/Compare.tsx`. 상태는 URL에 저장합니다(예: `?tab=compare&a=2026-09-01..2026-09-30&b=2025-09-01..2025-09-30`). 자주 보는 비교를 즐겨찾기처럼 다시 열 수 있습니다.
- 먼저 끝나 있어야 하는 작업
  - ARC-1(캐시): 기간 두 개를 계산하므로 부하가 두 배입니다.
  - ARC-2(파일 분리)
  - ACC-3(다양성 보정)
  - DQ-6(누락 감지)
- 있으면 좋은 작업: FEAT-2(청취 시간), FEAT-1(발매연도).

**완료 기준**

- 2026-09 vs 2025-09처럼 두 달을 고르면 모든 블록이 표시됩니다.
- 길이가 다른 두 기간(예: 7일 vs 30일)을 일평균 기준으로 비교할 수 있습니다.
- 월간 프롬프트의 "직전 달 비교" 수치와 Compare(해당 달 vs 직전 달) 수치가 일치합니다.
- URL을 복사해서 새로 열면 같은 비교가 열립니다.

**Claude Code 검토 요청**: 연간·월간·주간 프롬프트의 비교 계산이 지금 어디에 어떻게 구현되어 있는지, 공통 함수로 뽑아낼 수 있는지 확인해 주세요.
