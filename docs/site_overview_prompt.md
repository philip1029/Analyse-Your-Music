# Analyse-Your-Music 기능 정리 (AI에게 붙여넣는 프롬프트)

> 아래 전체를 AI에게 붙여넣고 맨 끝의 "요청" 부분을 원하는 질문으로 바꿔서 사용하세요.

---

당신은 개인용 음악 청취 분석 웹앱의 기획·개발 조언자입니다. 아래는 제가 만든 앱 **Analyse-Your-Music**의 현재 기능을
있는 그대로 정리한 것입니다. 이 내용을 바탕으로 **추가하면 좋을 기능, 고치거나 개선할 부분, 우선순위**를 제안해 주세요.
(계산 방식이나 한계도 함께 적었으니, 이미 있는 기능을 중복 제안하지 말고 한계를 보완하는 방향도 고려해 주세요.)

## 1. 프로젝트 개요
- 목적: 내 Last.fm 청취 기록(스크로블)을 시각화·분석하고, AI에게 물어볼 분석용 프롬프트를 만들어 주는 **개인용** 로컬 웹앱.
- 사용자는 1명(본인)이고, 서버는 내 컴퓨터에서만 돌린다 (`start.command` 더블클릭으로 백엔드 + 프론트엔드 동시 실행).
- 스택: 백엔드 FastAPI(Python, pandas) / 프론트엔드 React + Vite + TypeScript + Recharts (`frontend/src/App.tsx` 한 파일 약 1,500줄에
  모든 탭과 컴포넌트가 들어 있음) / 데이터는 DB 없이 CSV 한 파일(`data/<유저>_scrobbles.csv`).
- 데이터 규모: 약 43,700행, 기간 2024-06 ~ 현재(약 2년 4개월), 하루 평균 약 44곡.
- 외부 연동: Last.fm API(최신 스크로블 수집, 아티스트 태그 조회, 곡 길이 조회). 아티스트 태그는 `backend/cache/artists/`에
  JSON으로 캐시(약 300명분).

## 2. 데이터 구조 (가장 중요한 특성)
- CSV 열: `uts, utc_time, artist, album, track, source`
- `source` 열이 있다. **A** = Apple Music 재생 로그(Apple 개인정보 내보내기)에서 만든 기록(약 31,000행, 2024-06 ~ 2026-09-09),
  **L** = Last.fm에서 받은 기록(약 12,600행, 2025-01 ~ 현재).
- 두 출처가 일부 기간에 겹치고, Apple 연동 스크로블러의 문제(허구 백필, 이중 기록)가 있어서 **전처리 파이프라인**으로 정리한다(5장).
- 아직 없는 데이터: 곡의 **발매연도·장르** (Apple 라이브러리 내보내기에는 있으나 앱에 연결하지 않음), 곡 길이(전처리에서만 사용),
  사용자가 곡에 준 좋아요 정보.
- 한계: A 소스 중 약 198행은 아티스트가 비어 있음(컴필레이션 등). 시각은 모두 UTC로 저장하고 화면은 한국 시간(KST)으로 변환.

## 3. 화면 (프론트엔드)
### 3-1. 공통 상단 영역
- **"🔄 최신 스크롭 불러오기"** 버튼: Last.fm에서 마지막 저장 시각 이후의 새 스크로블을 받아 CSV에 붙이고, 이어서 전처리를 자동
  실행한다. 완료 메시지에 "새 스크로블 N개 · 가짜/중복 의심 N행 정리 · 보류 N건" 또는 전처리 실패 사유를 보여 주고 페이지를 새로고침한다.
- **날짜 범위 필터** (모든 탭에 적용): 버튼 프리셋(최근 7/30/90/180/365일, 2025년, 2026년, 전체 기간) + 직접 입력(시작일~종료일) 팝오버.
- 탭 6개: Overview / Listening / Music / Discovery / Taste / Data.
- 상단에 데이터 검증의 치명적 오류가 있으면 탭과 무관하게 항상 표시.

### 3-2. Overview
- 기본 통계 목록: 총 스크로블, 고유 트랙/아티스트/앨범 수, 첫/마지막 스크로블 시각.
- **음악 소비 다양성** 카드 3개(아티스트·트랙·앨범): 다양성 점수(정규화 엔트로피 0~100), 상위 10%가 전체에서 차지하는 비중, 최다 재생 항목.
- **청취 활동 히트맵**(깃허브 잔디 스타일, 연도별). **날짜 칸을 클릭하면 그날의 청취 기록 모달**이 열린다: 총 재생·고유 아티스트·트랙,
  많이 들은 아티스트 Top 5, 시간순 전체 재생 목록(시각/아티스트/곡/앨범).

### 3-3. Listening
- **청취 시계**: 시간대(0~23시)별 재생 분포를 시계 모양으로 표시(커스텀 SVG 컴포넌트).
- 주간 스크로블(요일별 면적 차트, "가장 바쁜 요일" 문구), 월별 청취 추이(선 그래프), 연도별 청취 추이(막대 그래프).

### 3-4. Music
- Top 10 아티스트 / 트랙 / 앨범 (재생 횟수 기준 막대 목록). 서버는 `limit` 파라미터로 개수 조절 가능하나 화면은 10개 고정.

### 3-5. Discovery
- "새로 발견한 음악": 전체 신규 트랙/아티스트/앨범 수, **월별 신규 트랙 수** 차트, **최근 처음 들은 곡** 목록(처음 들은 시각 포함).
- 정의: 데이터에서 처음 등장한 시점을 "발견"으로 본다 (데이터 시작 전에 들었던 곡도 신규로 잡히는 한계).

### 3-6. Taste (Last.fm 태그 기반 장르 분석)
- **장르/태그 분포**: 아티스트의 Last.fm 상위 5개 태그를 재생 횟수로 가중해 합산한 분포. "N / 전체 아티스트 기준"으로 태그를 이미 조회한
  아티스트의 비율을 함께 표시한다.
- **취향 변화(월별 장르 트렌드)**: 모드 2개 — *고정*(전체 기간 Top 태그의 월별 추이), *동적*(그 달의 실제 Top 5 태그 순위 변화).
  툴팁은 값 내림차순으로 정렬.
- **아티스트별 태그**: 아티스트 목록을 페이지 단위로 "더 보기"하며 Last.fm에서 태그를 조회(캐시). 별도로 **태그 캐시 미리 불러오기**
  버튼(20명씩)이 있어 분포·추이 분석의 커버리지를 높일 수 있다.
- 아티스트 표기 통일용 별칭 파일(`config/artist_aliases.txt`, `원본 -> 교체` 형식)로 태그 조회 시 이름을 치환한다.

### 3-7. Data
- **AI 분석용 프롬프트 생성** (복사 버튼 포함), 4가지 형태(전체 기간 / 연간 / 월간 / 주간):
  1. *전체 기간*(위쪽 날짜 범위 기준): 기본 통계, Top 10, 언어/지역권 월별 추이, 장르 비중·변화, 급상승/급하락 아티스트·장르,
     이탈/재발견 아티스트, 다양성·탐색 지표, 월·요일·시간대 분포, 최근 트렌드, 분석 요청 5개.
     (※ "신곡 vs 구곡" 항목은 발매연도 데이터가 없어서 "계산 제외"로 표기됨)
  2. *월간*: 선택한 달을 직전 달과 비교(기간 요약, 일별/주차별 흐름과 12개월 추이, 순위 + 신규/복귀 표시, 신규 발견, 시간대·연속 청취
     세션, 장르·언어권·다양성 비교, 반복 재생 트랙).
  3. *주간*: 월~일 한 주를 직전 주와 비교(요일별 표, 8주 추이 등 위와 동일 구조).
  4. *연간*: 선택한 해를 전년과 비교(월별 표 — 월별 재생 수·청취한 날 수·처음 들은 아티스트 수·월별 Top 아티스트, 연도별 추이,
     연간 하이라이트(가장 많이 들은 날 Top 5, 최장 연속 청취일, 하루 100회 이상 들은 날 수), 그 외는 월간과 동일 구조,
     반복 재생 트랙은 10회 이상 기준).
  - 기간 드롭다운은 최신순이며 기본값은 가장 최근에 **끝난** 기간. 기록이 기간 끝까지 닿지 않으면 "일부 기간"으로 표시하고 일평균 비교를 안내한다.
  - 새벽 3시간 이상 끊김 없는 세션에는 "자는 동안 켜져 있던 기록일 수 있음" 주석을 붙인다.
- **데이터 상태**: 총 행 수, 검증 경고 목록(빈 artist/album 개수, 잘못된 utc_time/uts, 미래 시각 등), "매핑된 아티스트 캐시 초기화" 버튼.

## 4. 백엔드 API (FastAPI)
`/api/health`, `/api/stats`, `/api/listening/{hourly|weekday|monthly|yearly|daily|day}`, `/api/music/top?category=artist|track|album&limit=`,
`/api/discovery/{summary|timeline}`, `/api/taste/{artists|tag-distribution|evolution?mode=fixed|dynamic}`, `POST /api/taste/cache-fetch`,
`/api/diversity`, `/api/validate`, `POST /api/refresh`, `POST /api/cache/invalidate-aliases`, `/api/debug/empty-album`,
`/api/ai-prompt`, `/api/ai-prompt/periods?period=`, `/api/ai-prompt/period?period=year|month|week&anchor=`.
- 대부분 `start`/`end` 쿼리로 기간 필터. 데이터 로딩 시 빈 값 정리, `uts+artist+track` 완전 중복 제거를 공통으로 수행한다.
- 인증·사용자 구분은 없음(로컬 전용). 요청마다 CSV를 읽어서 계산하며 별도 DB·캐시 계층은 없다(태그 캐시 제외).

## 5. 데이터 파이프라인 (스크립트)
- `scripts/callData.py`: Last.fm API로 새 스크로블 수집(source=L).
- `scripts/build_apple_sessions.py`: Apple 재생 로그에서 실제 재생만 뽑아 A 소스 생성(PLAY_END 조각 병합, 50%/240초 재생 규칙, 아티스트는
  컨테이너/라이브러리 조회로 채움).
- `scripts/detect_fake_scrobbles.py` + `scripts/preprocess.py`: 허구 백필·이중 기록 판정과 제거. **새로고침 버튼에 연결**돼 새 기록에
  자동 적용. 기본 규칙: Apple 로그가 있는 구간은 로그 대조로 제거, 로그가 없는 구간은 "곡 길이만큼 떨어진 2줄 + 양쪽이 다른 곡과 같은 초에 겹침"일
  때만 제거(약 15%는 실제 청취를 지울 수 있는 추정). 나머지 의심 기록은 지우지 않고 보류. 백업과 제거 기록(`data/preprocess_removed.csv`) 유지.
  곡 길이는 Apple 로그/라이브러리 → Last.fm `track.getInfo` 순으로 조회·캐시.
- `scripts/fill_missing_artists.py`: A 소스의 빈 artist를 Apple의 Play History Daily Tracks(곡명→아티스트), 같은 앨범의 유일한 아티스트,
  수동 지정으로 채움.
- 스크로블러: 앞으로 iPhone/Mac에서 FastScrobbler 사용 예정(Apple Music API 옵션은 끔, Listening History 자동 스크로블은 켬).

## 6. 이미 알고 있는 한계·미완료
- 새 Apple 내보내기를 받으면 A 소스를 다시 만들고 **A와 L의 중복을 합치는 단계**가 필요한데 아직 자동화되어 있지 않음.
- 이번 주(10/08~10/18)에 스크로블 누락 구간이 있음(Apple 사본으로 나중에 채울 예정).
- 발매연도/장르(Apple 라이브러리 기준, 내 스크로블의 약 85%에 연결 가능)를 앱에 아직 붙이지 않음.
- 프론트엔드가 단일 파일(App.tsx)이고 모바일 반응형·다크 모드·로딩/에러 UX가 미흡함. 날짜 필터를 바꾸면 모든 탭이 다시 계산됨.
- 태그 기반 분석은 아티스트 태그 캐시 커버리지에 의존(미조회 아티스트는 제외).
